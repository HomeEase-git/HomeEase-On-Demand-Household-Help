# Worker Verification Documents

This document consolidates all worker verification requirements for the HomeEase platform, organized by category and mapped to the current data model.

---

# Identity Documents

> **Current `KycDocumentType` values:** `GOVERNMENT_ID_FRONT`, `GOVERNMENT_ID_BACK`, `SELFIE`

These documents are required for identity verification.

- **Government-issued ID (Front)**
  - Any valid Philippine government-issued ID such as:
    - UMID
    - Driver's License
    - Philippine Passport
    - PhilHealth ID
    - National ID (PhilSys)
    - Other valid government-issued IDs

- **Government-issued ID (Back)**

- **Selfie**
  - Used for AI-assisted face matching against the uploaded government ID.
  - Acts as a soft verification signal during identity verification.

---

# Clearances

> **Currently missing from the schema.**  
> These should either be added as new `KycDocumentType` enum values or handled under a separate document category.

## Required

### NBI Clearance

- Strongest standardized criminal-history/fraud prevention signal in the Philippine context.
- Considered the most important missing document type.

### Barangay Clearance

- Local-level character reference.
- Easily obtainable by workers.

## Optional

### Police Clearance

- Complements the NBI Clearance.
- May be required depending on the Local Government Unit (LGU).

### Cedula (Community Tax Certificate)

- Low-cost proof of residency and local standing.

# Professional Documents

## Resume

- **Required**
- **PDF only**
- Parsed using the Claude API to extract:
  - Skills
  - Years of experience
  - Areas of expertise
  - Mastery level

## Certifications

- **Optional**
- **PDF only**
- Examples:
  - TESDA Certificates
  - Trade Certifications
  - Other Professional Certificates

Stored in the `Certification` model with:

- `documentUrl`
- `issuer`
- `issueDate`
- `expiryDate`
- `verificationStatus`

# Legal / Contractual Requirements

## Worker Service Agreement

This is not a document upload but a mandatory acknowledgement.

The worker must:

1. Accept the agreement inside the application.
2. Have the acceptance recorded in the `ContractAcceptance` model.
3. Receive a downloadable PDF copy generated by the system.

# Implementation Notes

## 1. Extend `KycDocumentType`

The current enum only includes:

- `GOVERNMENT_ID_FRONT`
- `GOVERNMENT_ID_BACK`
- `SELFIE`
- `RESUME`
- `CERTIFICATION`

It should be extended to include:

```ts
enum KycDocumentType {
  GOVERNMENT_ID_FRONT
  GOVERNMENT_ID_BACK
  SELFIE
  RESUME
  CERTIFICATION

  NBI_CLEARANCE
  BARANGAY_CLEARANCE
  POLICE_CLEARANCE
  CEDULA
}
```

Alternatively, clearances may be implemented as a separate document category if preferred.

---

## 2. Supported File Formats

### Identity Documents

- JPG
- JPEG
- PNG

### Clearances

Allow both:

- PDF
- JPG
- JPEG
- PNG

This reduces friction since many workers only possess printed copies or phone photos of these government-issued documents.

### Resume

- PDF only

### Certifications

- PDF only

---

## 3. Worker Verification Levels

Consider implementing progressive trust tiers instead of requiring every document before activation.

### Tier 1 (Minimum Requirements)

- Government ID (Front)
- Government ID (Back)
- Selfie
- NBI Clearance

Workers can begin accepting jobs after passing Tier 1 verification.

### Tier 2 (Higher Trust)

Additional verification through:

- Barangay Clearance
- Police Clearance
- Cedula
- Certifications

Tier 2 workers may receive:

- Higher visibility
- Greater client trust
- Priority in search results
- Eligibility for premium or specialized jobs
